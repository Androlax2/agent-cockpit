# A provider has several accounts, listed by the owner in launch order, and the daemon records the account of each launch

Status: accepted

Issue #59, part 1. The layout and the order were decided by Theo (2026-11-08); the record per
launch follows #858's rule that the account a session ran on is the daemon's record.

- **Accounts are the owner's list.** `[accounts] <provider> = [names]` in the owner's file, in
  the order a sandboxed launch tries them; a project file cannot set it. A provider without a
  list has `default` alone, so #968's single credential works unchanged. Names follow
  `cockpit_usage::AccountName`, the key of the quota records, checked again by
  `cockpit-config`, which depends on no product crate.
- **One folder per account.** An account's credential files sit in
  `provider-credentials/<provider>/<account>/`, read by #968's rules (`0600` or `0400`, one
  line, one file per account); `default`'s stay in the provider's folder itself.
- **A launch takes the first account holding a credential.** One without a credential is
  passed over (`doctor` names it); an unusable one refuses the launch, naming the account,
  rather than silently using the next.
- **Only a first launch picks.** A restart, wake, resume or restore keeps the account its
  conversation runs on (report 18); when that account is no longer listed or holds no
  credential, the relaunch is refused rather than moved to another account.
- **The account is recorded per launch, never read back.** `session_launches.account` is
  written in the transaction that records the launch; a session's account is its latest
  launch's. An unsandboxed launch signs in from the owner's home and records none.
- **Rejected:** folders discovered without a list (no order, and a stray folder would become
  an account); a project-level account choice (accounts are the owner's grant).

Evidence: `crates/cockpit-daemon/tests/sandbox.rs`
(`a_sandboxed_launch_runs_on_the_first_listed_account_with_a_credential`,
`an_account_without_a_credential_is_passed_over_for_the_next`,
`an_unusable_credential_refuses_the_launch_naming_its_account`,
`an_unsandboxed_launch_runs_on_no_account`,
`a_restart_keeps_the_account_its_conversation_runs_on`,
`a_restart_whose_account_lost_its_credential_is_refused_naming_it`),
`crates/cockpit-config/tests/account_settings.rs`.
