# Draft pull requests do not execute workflow jobs

Theo's direct decision on 2026-11-02 supersedes the rejection of draft skipping in
[the earlier CI cost decision](2026-11-01-397-ci-cost.md). This is bounded #397
follow-through; the merged #531 baseline and measured-savings acceptance are separate.

All four PR-triggered workflows subscribe to `opened`, `synchronize`, `reopened` and
`ready_for_review`. Their PR-capable jobs reject `github.event.pull_request.draft`
before runner allocation, including matrix expansion. Generated draft release proposals
have no exception. Existing non-PR-only jobs and tag-only release gates remain intact;
downstream jobs retain their default successful-dependency requirement.

Main pushes, release tags, schedules, manual dispatches and docs publication events keep
their existing conditions. PR path filters and the five required CI context names remain
unchanged. GitHub can still create skipped run/check records; this does not promise that
drafts disappear from Actions history or cancel a run already started before conversion
to draft.

Drafts cannot merge. After marking ready, wait for the automatically triggered checks
on the exact head to execute and pass; skipped draft results never establish tested code
or authorize a merge. No required-check settings or repository protections change.

`tools/tests/test_workflow_drafts.py` exercises the actual job expressions with draft,
ready and non-PR contexts, checks the readiness subscription, and preserves selection
and publication restrictions. Hosted draft/ready verification establishes GitHub's actual
execution behavior; local expression tests do not implement the Actions scheduler.
