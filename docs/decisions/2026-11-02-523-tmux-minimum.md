# Require tmux 3.6 for reliable child reaping

Issue #523, investigating #537. Decided by Theo: Option A, then approval of the
implementation plan on 2026-11-02.

- **Require tmux 3.6 or newer for both client and running private server.**
  Upstream [fix fa5f3cef](https://github.com/tmux/tmux/commit/fa5f3cef3d651b0eb9abfa77fc37ccade81679b5)
  restores child-exit notification after libutempter cleanup. Reject `next-3.6` and
  `3.6-rc…`, which may predate the fix. Preserve existing newer-version parsing.
  `Server::open` checks before configuration writes; it never kills old sessions.
- **Use Ubuntu 26.04 for candidate compatibility/responsiveness.** Its tmux package
  is 3.6a. Archive builds and clean install-check runners retain their platforms;
  ordinary required macOS developer CI stays enabled. Ubuntu 24.04/WSL2 users must
  upgrade tmux, including any already-running private server.
- **Retain failed candidates as failures.** A controlled real-libutempter experiment
  reproduced an unreaped zombie for 10.001944812 seconds with tmux 3.4; the same build
  with the upstream two-line fix reaped it in 0.041987636 seconds. The original CI
  runner's parent executable/signal history was not retained: this proves the
  dependency defect, not its retrospective occurrence on that destroyed runner.
  [Evidence and exact experiment receipts](https://github.com/Androlax2/agent-cockpit/issues/537#issuecomment-6583427737)
  remain separate from the required reviewed, exact-source candidate acceptance.
- **Rejected:** an older-version lifecycle workaround because it adds process
  management around a fixed dependency defect. Treating a zombie group as empty
  would weaken ownership/termination guarantees and is not an acceptable workaround.

Implementation: `crates/cockpit-tmux/src/version.rs`, `server.rs` and
`tests/fake_tmux.rs`; runner regression: `tools/tests/test_ci_bootstrap.py`.
