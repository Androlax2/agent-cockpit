# CI spends its minutes where the measurements put them; no merge queue

Issue #397. Theo asked for this scope on 2026-11-01, naming rust-cache per job among the
caches to add; the worker chose each change from the measurements below.

Measured on the 183 CI runs with today's job set (2026-10-31 00:57 to 2026-11-01 15:42 UTC,
every run since the legacy job left) and the 71 pull requests merged in that window, with
`gh run list` and `gh api repos/Androlax2/agent-cockpit/actions/runs/<id>/jobs`. Billed
minutes round each job up to the minute, macOS ×10 and Windows ×2. The repository is public,
so GitHub bills none of them; they still measure runner time and the five-job macOS limit.

| Per merged pull request | Pull request runs | `main` run | Total |
| --- | --- | --- | --- |
| Runs | 1.51 (27 of 71 had more than one) | 1 | |
| Runner minutes | 21.7 | 11.5 | 33.2 |
| Billed-equivalent minutes | 64.2 | 35.8 | 100 |

| Job (billed-equivalent minutes, both events) | Minutes | Typical run |
| --- | --- | --- |
| `greenfield-macos` | 3970 | 1.5–2.5 min, cache restored on 29 of 29 sampled runs |
| `greenfield-wsl2` | 1586 | 4–5 min: `setup-wsl` 1.3, uncached build and tests 3 |
| `greenfield` | 836 | 5–7 min, uncached; last to finish in 69 of 126 green runs |
| `docs` | 653 | 3–4 min, of which `cargo install lychee` 2.5–3.5 |

A green run takes 5.1 minutes from start to last job (p90 6.8); jobs wait about 3 s for a
runner, so the platform jobs never delay a merge. A pull request merges 8.5 minutes after it
opens (median; p75 17, p90 34).

- **`docs` installs lychee's release binary, checksum verified, instead of compiling it.**
  About 3 minutes off every docs run, which also takes `docs` off the critical path. It no
  longer needs a Rust toolchain.
- **`greenfield` restores the same pinned `Swatinem/rust-cache` as `greenfield-macos`, saved
  only on `main`** (the rules of `2026-10-31-127-platform-build-cache.md`). It is the job every
  merge waits for, so its build time is the merge time. The caches use 7.3 of the repository's
  10 GB, nearly all of it stale macOS entries (0.55 GB each); GitHub evicts the least recently
  used first, and the entries in use are read on every run.
- **The macOS and WSL 2 jobs run on a pull request only when it changes a crate they build**
  (`tools/ci-jobs.py`): the crates they test or whose programs their tests start
  (`PLATFORM_ROOTS`) and every crate those depend on, read from the manifests, plus the root
  manifests and `ci.yml`. No dependency of the daemon reaches `main` without its platform run,
  the rule #127 set. That leaves `cockpit-workspace-rules`, the Makefile and other workflow
  files: run on the 93 merged pull requests' files, this skips the platform jobs for 3 of the
  86 that reach the greenfield job. Small, but it costs no proof. A skipped job reports
  success, so the ruleset's five required checks stay as they are.
- **`prerelease.yml` parses again.** A colon followed by a space inside a plain `run:` scalar made GitHub reject the
  file, record a failed run on every push (141 so far) and offer no dispatch.
  `tools/tests/test_workflow_syntax.py` guards every workflow.
- **No merge queue.** GitHub offers it only on repositories owned by an organization; this one
  is owned by a user. It would also add a `merge_group` run per pull request to today's 1.51,
  while `main` already merges without requiring an up-to-date branch: a pull request is rebased
  only on a real conflict. Auto-merge plus a rebase on conflict stays the flow.
- **Rejected: no CI on draft pull requests.** No pull request in this repository was ever a
  draft; skipping would save nothing and leave a skipped-means-green window at
  `ready_for_review`.
- **Rejected: platform jobs only for crates with OS-specific code, `main` as the backstop.**
  `main` runs cancel each other and nobody is alerted when one fails, so a break would surface
  on an unrelated pull request.
- **Rejected: selecting `main` pushes by their diff.** `main` runs cancel each other (24 of 72);
  a docs-only merge cancelling the run of the crate merge before it would leave that change
  unproven on every platform.
- **Unchanged:** WSL 2 stays uncached (`2026-10-31-127-platform-build-cache.md`); the release
  workflow, which already builds on pull requests only for its own machinery.
- **Open (`validate`):** the gain of each change, and the acceptance's before/after table over
  15 merged pull requests, are measured after this merges and recorded on #397.

Regression tests: `tools/tests/test_ci_jobs.py`, `tools/tests/test_ci_bootstrap.py`,
`tools/tests/test_workflow_syntax.py`.
