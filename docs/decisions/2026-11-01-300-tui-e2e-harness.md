# The TUI's end-to-end tests drive `cockpit tui` in a test-owned tmux terminal and wait on its output

Issue #300. Decided by the worker: the issue names the harness's helpers and its rule
(waits use events, never sleeps), but not how to get events from a terminal or how to
shorten idle sleep.

- **The owner's terminal is a tmux server the test owns** (`-S` in the scratch home),
  running `cockpit tui` in its one pane. Keys travel the path a human's do: the terminal,
  the client `cockpit tui` attaches to the daemon's private server, the manager's active
  pane. So a viewer focused on attach (#271) fails the suite. Running the TUI directly in
  the private server would bypass `cockpit tui` and the attach.
- **Screen waits block on `%output`** from a control-mode client (`-C`, `ignore-size`) of
  that server. After each reported write the screen is read again with `capture-pane`, and
  the wait gives up after 30 s, showing that screen. State waits follow the daemon's change
  feed through `cockpit-client`. A snapshot is compared by waiting until the screen matches,
  because a capture can land mid-redraw.
- **Idle sleep runs on `cockpit-daemon`'s example `cockpit-e2e-daemon`.** It runs the
  binary's own `serve` with a 3-second idle window and a 200 ms tick. The configuration's
  30-minute floor and the product binary have no test switch.
- **`cockpit-tui` drives tmux as a process.** The crate-graph rule
  (`tui -> client/protocol/diagnostics only`) counts dev-dependencies, so the tests cannot
  link `cockpit-tmux`. They build `cockpit`, the daemons and the hook with Cargo, as the CLI's
  tests build the daemon.
- **The fake agent is a shell script.** A line starting with `!` runs as a command (Claude
  running a tool), any other line gets an answer naming the conversation's first message.
  That shows whether a restart, wake or resume kept the conversation.
- **The modules that need the agent channel build on Linux only**, under one `cfg` in
  `tests/e2e/main.rs`: the channel refuses every sender on macOS until it reads process
  trees there (#336). The macOS job runs the rest.
- **The approval test presses `y` again 300 ms after the daemon's grace refusal**, as the
  owner does, until the TUI's grace covers the daemon's (#337). It is the one pause in the
  suite: nothing on the screen or the feed marks the end of the daemon's grace.
- **Rejected:** a `COCKPIT_*` variable that shortens idle sleep in the product binary: a test
  switch every installation would carry. A fixed sleep before reading the screen: slow and
  flaky. A new test-support crate: one more workspace member and `Cargo.lock` entry for code
  only these tests use.
