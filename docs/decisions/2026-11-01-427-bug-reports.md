# Bug reports are drafts in their own crate, limited per fingerprint and per session, sent only from the owner's CLI

Issue #427. Decided by the implementing session, within report 12 (the support bundle's
privacy rule) and report 17 (agent verbs).

- **New crate `cockpit-bug-reports`, allowed to import `cockpit-turso` only.** It owns the
  drafts, their fingerprint, the daily limit and the issue text a send hands the owner. The
  daemon passes in its facts (version, platform, providers) and writes the bundle through
  `cockpit-diagnostics`. The rule `bug-reports -> the database only` is in
  `crates/cockpit-workspace-rules/tests/crate_graph.rs`.
- **The fingerprint is `cockpit-<version>/<kind>/<component>`.** An agent picks `timeout`,
  `unreachable`, `internal` or `other` and may name a component. `panic`, `stall` and `crash`
  are refused from agents: only the daemon observes them. The duplicate search runs only for
  a specific fingerprint (not `other` without a component), so unrelated reports do not match.
- **`--requested-by-owner` is an agent's claim.** The agent socket cannot prove the owner
  asked, so the claim lifts only the per-fingerprint limit, never the owner's review. Every
  agent's new drafts are capped at 5 per session per UTC day, so a looping agent cannot flood
  the owner. Owner drafts (`cockpit bug-report new`) have no limit.
- **A limited repeat merges into today's draft.** It counts one more occurrence and appends its
  description while the draft stays under 8000 characters. Once today's draft is sent or
  discarded, a repeat opens nothing until the next UTC day.
- **The bundle is written when the draft is created,** a snapshot of the logs at the time of
  the fault, outside the transaction. A failure is recorded on the draft, which is kept. The
  issue names the bundle's file name and contents, never the owner's path. The environment
  text leaves out why a provider is unavailable, because those reasons can hold paths.
- **Daemon detection.** A request's panic, a long-lived worker's panic, a request still running
  past its lane's budget (control 30 s, stop 2 min, bulk 30 min, in `Limits::stall_budgets`),
  and `internal` answered 3 times within 10 minutes for one command kind (not for the bug
  report commands, whose `internal` comes from the database a draft would need). Faults go through a
  bounded queue to a supervised worker. Its own panics are not filed, so a fault that crashes
  it cannot loop.
- **A crash is a `daemon.running` marker left in the state directory.** The daemon writes it
  after the last step of its start that can fail and removes it when the `Daemon` drops.
  `serve` now stops cleanly on SIGTERM and SIGINT (5 s for blocking work), so only a kill, a
  crash or a power loss leaves the marker.
- **Send happens in the CLI, with the owner's tools.** By default `send` opens the prefilled
  `bug-from-cockpit.yml` URL with `xdg-open` (`open` on macOS), or prints it with `--print`.
  `--gh` files it with the owner's `gh` login and records the issue URL. The daemon never
  touches the network. An existing issue found with `gh issue list` is offered instead, and
  `--anyway` files a new one. Without `gh`, the search URL is printed for a check by hand.
  Opening the browser or printing the URL leaves the draft a draft: nothing proves the owner
  submitted it, and a draft marked sent would stop the day's repeats of a bug never filed.
  `send ID --filed URL` records the issue the owner submitted or added to.
- **The TUI part waits for a design** (#471). No FigCraft frame covers drafts, and the project
  builds no interface without one. Decided since: a plain-text version ships first
  (`2026-11-01-471-bug-reports-in-the-tui.md`).
