# The M1 TUI is a plain Ratatui column in a daemon-owned manager session, polling until the change feed exists

Issue #35. Decided by Theo for the diagnostics edge (#176) and the pane's location (#178);
the rest by the worker, with the reasons below.

- **cockpit-tui may depend on cockpit-diagnostics (#176, option A).** The TUI writes its own
  log, so each command it runs is counted for the next pruning (decision 17). The crate-graph
  rule `tui -> client/protocol/diagnostics only` allows exactly that edge; cockpit-web keeps
  `frontends -> client/protocol only`. Regression rows in
  `crates/cockpit-workspace-rules/tests/crate_graph.rs`.
- **The approval pane is a region of the TUI process for M1 to M5 (#178, option A).** M6
  revisits whether it moves to its own pane or window. The pane's input rules (#166) live in
  `crates/cockpit-tui/src/pane.rs`: approve is `y` only, input is ignored for 1 s after a
  request shows or the pane takes focus (the daemon's 2 s grace stays the backstop), and
  focus never moves to a new request while the owner types (`i` starts typing).
- **The daemon owns the manager tmux session; the client supplies the words.** `manager-open`
  creates the `cockpit` session once (column, then a viewer split beside it) and answers how
  to attach; `session-show` wakes an asleep session and shows it in the viewer. The daemon
  never guesses where cockpit-tui is installed: `cockpit tui` finds it beside itself, resolves
  the socket (the TUI may not read configuration) and passes both.
- **The TUI polls the lists every second until sessions and checkouts are on the change
  feed.** #41 serves `subscribe`, but no producer publishes those entities yet. The TUI
  already applies recorded batches whole (`Board::apply`), which is what its tests drive.
  Superseded by `2026-10-31-199-change-feed-projector.md`: the TUI now follows the feed.
- **`provider-list` names the providers the daemon was wired with** until readiness (#50)
  says which ones are usable.
- **Rejected:** the CLI creating the tmux session itself, because the daemon is the only
  owner of the private tmux server; a TUI-side config read, because it breaks the crate graph.
