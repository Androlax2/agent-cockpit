# A turn's outcome rides on the agent's report and lasts until its next turn starts

Issue #183. Decided by the worker, completing the provider contract decision of #33
(`2026-10-31-33-provider-contract.md`, "Outcome is normalized but not reported").

- **The provider contract's type, mirrored on the wire.** `cockpit-sessions` stores
  `cockpit_provider_api::TurnOutcome` (completed, failed with an optional reason, quota
  stopped); `cockpit_protocol::TurnOutcome` mirrors it as a `kind`-tagged object, so a
  reason exists only on a failure, and the daemon converts between the two. Columns `outcome` and
  `outcome_reason` on `session_reports` (sessions migration 3) refuse a reason without
  `failed`.
- **An outcome means waiting.** Reporting one sets the state to waiting; `working` with an
  outcome is refused, like `working` with a question. Rejected: an outcome independent of
  the state, which would let a session read "working, last turn failed".
- **A new turn or launch clears it.** A `working` report clears the outcome, and so does
  the first report of a new launch; a `waiting` report without one (the idle prompt after
  a `Stop`) keeps it. Rejected: keeping the last outcome
  through the next turn, which shows a stale failure while the agent works.
- **A failure's reason is the provider's own word**, at most 80 characters, under the same
  text rules as the other report fields. The Claude Code bridge leaves out a reason the
  channel would refuse and cuts a long one, so the outcome always arrives.
- **`outcome` is reported with `events`**: both reach Cockpit only through the hook bridge,
  so an adapter wired without it reports neither.
- **`Reply::AgentReported` boxes its report**, as the other large replies do, so the
  client's error type stays small.
