# A development build runs profile `dev`, and a legacy Cockpit keeps the default profile until the cutover

Issues #196 and #134. Decided by the worker, from the issues' acceptance criteria; the reasons
below are the ones that settled each open choice.

- **The build decides the default, not the cargo profile.** A `cockpit` with a release bundle
  manifest beside it (`<prefix>/share/cockpit/manifest.json`, #96) runs profile `cockpit`; any
  other build runs `dev`. A release built with `cargo build --release` but not installed from a
  bundle is a development build: only the bundle is what Theo installs
  (`crates/cockpit-config/src/profile.rs`).
- **An inherited `COCKPIT_PROFILE=cockpit` is ignored by a development build, visibly.** Every
  agent the installed Cockpit launches inherits it; obeying it would point a `cargo run` in
  that agent at the installed daemon. `config show` and `doctor` name the variable as ignored;
  only `--profile cockpit` reaches the default profile
  (`crates/cockpit-cli/tests/profiles.rs`).
- **Precedence is flag, variable, command name, build.** The variable is what launched agents
  carry; the command name (`cockpit-next`) is what a person types.
- **A profile name is a plain lowercase name of at most 24 characters that names no program.**
  `cockpit-daemon` or `cockpit-tui` must never read as profile `daemon` or `tui`.
- **Units carry their profile on an `X-Cockpit-Profile=` line** (an XML comment in a plist).
  `doctor` lists installed profiles from that line, and a `cockpit.service` without it is the
  legacy Cockpit's. The launchd label is `io.github.androlax2.cockpit[-<name>]`.
- **A legacy Cockpit is a `cockpit.service` without the profile line, or a `cockpit` on `PATH`
  that is not this program**, shadowed or not. While one is found, `cockpit daemon install`
  refuses the default profile and proposes `--profile next`; the install script (#97) must go
  through `cockpit daemon install` so it inherits the refusal.
- **`doctor` is the minimal one this lane needs**: the active profile and what it owns, then
  every other installation. The readiness checks of #50 extend it.
- **Rejected:** a `cockpit-dev` binary name for development builds, because `cargo run` and the
  test harnesses run `cockpit`; selecting the profile from `debug_assertions`, because a local
  `--release` build would then reach the installed daemon.
