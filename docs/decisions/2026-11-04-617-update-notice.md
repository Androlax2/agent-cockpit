# Torlek announces a newer release at most daily and prints the update commands, never runs them

Issue #617. Frequency and reminders decided by Theo on 2026-11-04 (Option A); the rest by the worker.

- **Check at most once a day, only when an interactive command runs.** `torlek doctor` and `torlek session list` (after it succeeds), with a terminal on stdout and stderr, no `TORLEK_SESSION`, and automatic checks on. A failed or offline attempt counts as the day's attempt, so a down or rate-limiting source is asked once a day, within a 3 second `curl --max-time`, never in the daemon's start path. The answer is cached in `update.json` in the profile's state directory. A notice is printed at most once a day on stderr, so piped and machine-readable output stays clean.
- **Later postpones every notice for 3 days; Skip silences that version** until a newer one is published. `torlek update checks off` is the persistent switch; `torlek update check` always asks.
- **Nothing changes on a check.** The only network use is one request for the official repository's release list. Update means printing the README's archive commands for the new version and `torlek daemon install`, the existing way to replace a running daemon; the owner runs them. No competing installer.
- **The installed identity is the bundle manifest.** Its version gives the channel and its platform the archive to look for, so a build outside a bundle has nothing to compare and never checks. The tag, not GitHub's prerelease flag, decides the channel: alpha offers alpha, beta or stable; beta offers beta or stable; never a downgrade, a draft, a `-dev` or other tag, or a release lacking `torlek-vVERSION-PLATFORM.tar.gz` and `SHA256SUMS`.
- **The release list is untrusted text.** The link shown is built from the tag, not taken from the list, and control characters are removed from the notes, along with zero-width and bidirectional formatting characters, before they reach a terminal.
- **Unsupported:** installations that are not a release archive unpacked in `~/.local/lib/torlek`, the README's route, get no commands, since the printed ones would install beside them (packages are #562, #563 and #565; macOS is #568). `torlek tui` does not announce: its screen replaces the terminal, so the notice would be consumed unseen.
- **The first 30 releases are read, newest first, and the choice is by version, not list order.** Releases are only alpha, beta and stable tags (nightlies are dry runs), so the list stays short.
- **`curl`, version comparison by hand, one module.** `curl` is already required by the install route and keeps the tests on a stand-in program; an HTTP client crate or `semver` would be a new dependency, and the grammar here is three numbers plus an `alpha.N` or `beta.N` suffix. The code is `crates/cockpit-cli/src/update.rs`; tests are its `update/tests.rs` and `tests/update.rs`.
- **Rejected:** checking weekly (a fix would take a week to be announced), automatic checks off by default (the feature would reach nobody), an interactive prompt on a command (it would block scripts and agents), and a global hook in `main` (the three call sites stay greppable).
