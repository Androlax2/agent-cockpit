# CI efficiency baseline implementation plan

> **For agentic workers:** Use the executing-plans workflow; implementation stays in this lane.

**Goal:** Make issue #397's baseline reproducible without spending CI minutes on experiments.

**Architecture:** Read cached GitHub REST/CLI JSON offline, calculate a bounded merged-PR
cohort, and report unavailable measurements explicitly. Keep collection separate from analysis.

**Tech Stack:** Python standard library, unittest, existing GitHub CLI.

**Spec:** Issue #397 and the overnight assignment: two-week census, bounded requests, fixture
tests, no workflow pushes/settings changes, and no invented 15-PR before/after acceptance.

## Global constraints

- No new dependencies, manifest changes, host actions or live acceptance.
- Preserve all platform checks and draft checks; release automation belongs to another lane.
- At most two concurrent retrievals; cache every response under `.handoff/ci-397/`.
- Actual billed minutes and rounded weighted runner equivalents are different metrics.
- Required medium code-review and independent review precede delivery.

## Review focus

- Reruns: count every job attempt, not only the last attempt.
- Missing or truncated evidence: refuse totals rather than silently undercount.
- Skipped jobs: do not charge them; cancelled jobs with timestamps still consumed time.
- Draft cycles: measure from the last ready event before merge, not always creation.
- Attribution: PR jobs belong to the PR; its merge SHA identifies the main run.
