# Cockpit M1 live acceptance

## 1. Start the new Cockpit on a scratch home

1. How this guide works: each step says what to do. Steps with a command open an approval window: read the command, approve it, and its output comes back here. Questions: type your answer in this panel. Nothing here uses your installed cockpit's state; everything lives in /tmp/cockpit-acceptance-UID (your user id). Claude still runs your own Claude Code login and hooks. Claude runs outside greywall in this walk (your real claude binary, in the scratch project demo only), because greywall hides this clone's build from it.
2. Approve the command below. It starts this clone's daemon on the scratch home (it says so if it already runs) and prints where everything is.
   run: bash tools/acceptance/run.sh start
3. Approve the command below. It prints the version of this clone's build.
   run: bash tools/acceptance/run.sh cockpit version --all
4. Approve the command below. Every path it prints should start with /tmp/cockpit-acceptance-, and sessions.idle_sleep_after_minutes should be 30.
   run: bash tools/acceptance/run.sh cockpit config show
5. Approve the command below. It should print one line: claude resume.
   run: bash tools/acceptance/run.sh cockpit provider list
6. Look at the outputs above.
   ask: Was any path outside /tmp/cockpit-acceptance-, or anything else surprising? (none is a fine answer)

## 2. Open the TUI and start three sessions

1. Approve the command below. It opens the TUI in a new, fully opaque window: a session list on the left (project demo) and a viewer on the right. Click that window to use it.
   run: bash tools/acceptance/run.sh tui-window
   ask: Did the TUI open, opaque, with project demo in the list? How long did it take?
2. In the TUI, press N (shift+n). A New session form opens with Project demo and Agent claude filled in. Press Tab twice to reach First message, paste the text below, leave Where on in place, and press Enter.
   copy: Say hello in one line, then wait without doing anything else.
   ask: Did a card appear under demo? How long after Enter, and what does it show?
3. Press j or k until that first card is selected, then press Enter. The viewer on the right shows Claude's terminal. If Claude asks whether to trust the folder, click into the viewer and answer yes. Leave this first session alone from now on: section 6 checks that it falls asleep by itself.
   ask: Did the viewer show Claude within a second, and did Claude answer the first message?
4. Click the session list (left) to give it the keys. Press N again. Press Tab three times to reach Where, press Right so it says new clone, press Tab, type accept-clone as the branch, then press Enter.
   ask: Did a second card appear under demo? Select it and press Enter: does the viewer run in .parallel/demo/accept-clone?
5. Approve the command below. It starts a third session from the CLI. Sections 3 to 5 use this third session.
   run: bash tools/acceptance/run.sh session new --prompt "Reply OK, then wait."
6. Look at the TUI without pressing anything.
   ask: Did the third card appear by itself? How long did it take?

## 3. Restart, sleep, wake, exit, resume, daemon restart

1. Click the list, select the third card (j/k), press r, then y to confirm. Then press Enter, click into the viewer and ask Claude: what did you reply before?
   ask: Did it come back in the same conversation? Anything odd on the card while it restarted?
2. Approve the command below. It puts the third session to sleep.
   run: bash tools/acceptance/run.sh session sleep
3. Look at the third card and the viewer.
   ask: Does the card say asleep, and is its terminal gone from the viewer?
4. Click the list, select the third card and press Enter: that wakes it. Click into the viewer and send Claude the message below (paste, then Enter).
   copy: What was the first thing I asked you?
   ask: Did it wake on Enter, keep its conversation and answer?
5. Approve the command below. It ends (exits) the third session.
   run: bash tools/acceptance/run.sh session end
6. Approve the command below. It resumes the third session in its old conversation.
   run: bash tools/acceptance/run.sh session resume
7. Look at the TUI.
   ask: Did the third card leave the list when it ended and come back on resume, in the same conversation?
8. Approve the command below. It kills the daemon hard (kill -9); the sessions keep running.
   run: bash tools/acceptance/run.sh kill-daemon
9. Look at the TUI for a few seconds.
   ask: What does the TUI show without a daemon? Does it stay usable and say what is wrong?
10. Approve the command below. It starts the daemon again.
    run: bash tools/acceptance/run.sh start
11. Look at the TUI and the three cards.
    ask: Did the TUI reconnect by itself, and did every session come back without relaunching?

## 4. One ask run and one ask guide, end to end

1. In the TUI, select the third card and press Enter. Click into the viewer and send Claude the message below.
   copy: Run exactly this and show me its output: cockpit ask run --reason "acceptance check" 'printf "hello from the host\nGITHUB_TOKEN=ghp_abcdefghijklmnopqrstuvwxyz0123456789\n"'
2. Wait for the Waiting on you pane to appear under the session list (left column). It takes the keys. Read it before pressing anything.
   ask: Does it show the exact command, the directory and the reason? Were your first keys ignored for a moment?
3. Press m (shows the whole command), m again (folds it), then y to approve.
   ask: Did Claude receive "hello from the host" with the token shown as [redacted]? Anything in the pane that surprised you?
4. Click into the viewer and send Claude the message below. When the Waiting on you pane shows it, press x to decline.
   copy: Run exactly this and tell me the exit code: cockpit ask run --reason "decline check" 'echo should not run'
   ask: Did Claude get exit code 125 (declined)?
5. Click into the viewer and send Claude the message below.
   copy: Run exactly this and tell me what I answered: printf '# Pane guide\n## One\n1. Look at the sky\n   ask: What colour is it?\n2. Press y\n' | cockpit ask guide
6. The guide shows in the Waiting on you pane. Press y, type an answer, press Enter. On step 2 press y. Then press Tab to give the keys back to the list.
   ask: Did each step show one at a time, and did Claude repeat your answer?

## 5. An agent reports progress

1. Click into the viewer of the third session and send Claude the message below.
   copy: Run exactly these two commands, then stop: cockpit agent report --label "acceptance" --doing "checking cards" and cockpit agent report --needs-input "Pick A or B?"
2. Click the list. Look at the third card, then press n.
   ask: Does the card show !, waiting on you, the label and the doing text? Did n open that session?
3. Click into the viewer and send Claude the answer below.
   copy: A
   ask: Did the ! and waiting on you clear once you answered?

## 6. Latency feel and sleep after idle

1. Think back over the walk: the list updating, opening a session, the Waiting on you pane appearing.
   ask: Did anything take more than a second? Which, and roughly how long?
2. Wait until at least 30 minutes have passed since section 2, step 3 (when the first session answered). Then approve the command below; it lists the sessions.
   run: bash tools/acceptance/run.sh cockpit session list
3. Find the first session in the list (the oldest one in projects/demo).
   ask: Is it asleep? If not, how many minutes since section 2, step 3?
4. Approve the command below. It stops the scratch daemon and its sessions. The scratch directory stays as evidence.
   run: bash tools/acceptance/run.sh stop
5. Close the TUI window.
   ask: Anything else from the walk worth an issue? (none is a fine answer)
