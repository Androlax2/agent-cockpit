# Cockpit M1 live acceptance

## 1. Install from the clone, check the scratch home
1. Start this clone's daemon on a scratch home, never the installed cockpit. It prints the scratch directory, the claude it will launch, the commit and the TUI command.
   run: bash tools/acceptance/run.sh start
2. Check the programs are this clone's build.
   run: bash tools/acceptance/run.sh cockpit version --all
3. Check every path is under the scratch directory and the idle window is 30 minutes (`cockpit doctor` comes later, #50; this stands in for it).
   run: bash tools/acceptance/run.sh cockpit config show
4. Check claude is offered as a provider.
   run: bash tools/acceptance/run.sh cockpit provider list
5. Anything surprising so far: a path outside the scratch directory, a claude you did not expect, a slow start?
   ask: What did you notice? (none is a fine answer)

## 2. Start sessions, in place and in a fast clone
6. Open a new terminal and run the TUI command step 1 printed (it ends in run.sh tui). If the list ignores keys, click the left column.
   ask: Does the list show project demo, and how long did it take to appear?
7. Press N. Keep project demo and agent claude, paste the first message below, leave Where on in place, press Enter.
   copy: Say hello in one line, then wait without doing anything else.
   ask: Did a card appear under demo? How long after Enter, and what does it show?
8. Select that card and press Enter. Leave this session alone from now on: it is the one that should fall asleep by itself in section 6.
   ask: Did the viewer show Claude's terminal within a second, and did it answer the first message?
9. Press N again, set Where to new clone, branch accept-clone, no first message, Enter.
   ask: Did a second card appear under demo, and does its viewer run in .parallel/demo/accept-clone?
10. Start a third session from the CLI, in place. Sections 3 to 5 use this one.
   run: bash tools/acceptance/run.sh cockpit session new demo --prompt "Reply OK, then wait."
11. Look at the TUI without pressing a key.
   ask: Did the third card appear on its own? How long did it take?

## 3. Restart, sleep, wake, exit, resume, daemon restart
12. In the TUI select the third session, press r, then y.
   ask: Did it come back in the same conversation (ask it what it replied before)? Anything odd on the card while it restarted?
13. Put the third session to sleep.
   run: bash tools/acceptance/run.sh session sleep
14. Look at the card and the viewer.
   ask: Does the card say asleep, and is its terminal gone?
15. Wake it by message: select it, press Enter, then type a message to Claude in the viewer.
   copy: What was the first thing I asked you?
   ask: Did it wake on Enter, keep its conversation and answer?
16. Exit the third session from the CLI.
   run: bash tools/acceptance/run.sh session end
17. Resume it.
   run: bash tools/acceptance/run.sh session resume
18. Check the resumed session in the TUI.
   ask: Did the card leave the list on exit and come back on resume, in the same conversation?
19. Kill the daemon the hard way. Its sessions keep running in tmux.
   run: bash tools/acceptance/run.sh kill-daemon
20. Look at the TUI while the daemon is down.
   ask: What does the TUI show without a daemon? Does it stay usable or say what is wrong?
21. Start the daemon again.
   run: bash tools/acceptance/run.sh start
22. Look at the TUI and the three sessions.
   ask: Did the TUI reconnect by itself, and did every session reopen with its conversation and no relaunch?

## 4. One ask run and one ask guide, end to end (blocked by #270 and #268: skip until both are merged)
23. In the third session's viewer, send Claude this message.
   copy: Run exactly this and show me its output: cockpit ask run --reason "acceptance check" 'printf "hello from the host\nGITHUB_TOKEN=ghp_abcdefghijklmnopqrstuvwxyz0123456789\n"'
24. Wait for the approval pane under the viewer. Read it before pressing anything.
   ask: Does the pane show the exact command, its working directory and the reason? Were your first keys ignored for a moment?
25. Press m to unfold the whole command, m again, then y to approve.
   ask: Did Claude receive "hello from the host" with the token redacted? Anything in the pane that surprised you?
26. Send Claude a second message, then decline it with x when the pane asks.
   copy: Run exactly this and tell me the exit code: cockpit ask run --reason "decline check" 'echo should not run'
   ask: Did Claude get exit 125 (declined)?
27. Send Claude a guide to hand you.
   copy: Run exactly this and tell me what I answered: printf '# Pane guide\n## One\n1. Look at the sky\n   ask: What colour is it?\n2. Press y\n' | cockpit ask guide
28. Answer the guide in the pane: y, type an answer, Enter; then y on step 2.
   ask: Did each step show one at a time, and did Claude repeat your answer?

## 5. An agent reports progress (blocked by #268: skip until it is merged)
29. Send Claude this message.
   copy: Run exactly these two commands, then stop: cockpit agent report --label "acceptance" --doing "checking cards" and cockpit agent report --needs-input "Pick A or B?"
30. Look at its card, then press n in the list.
   ask: Does the card show the label, the doing text and that it needs you? Did n jump to it?
31. Answer Claude in the viewer.
   copy: A
   ask: Did the needs-you mark clear once you answered?

## 6. Latency feel and sleep after idle
32. Think back over the walk: list refreshes, opening a session, the approval pane appearing.
   ask: Did anything take more than a second? Which, and roughly how long?
33. At least 30 minutes after step 8, list the sessions.
   run: bash tools/acceptance/run.sh cockpit session list
34. Find the first session (in place, left alone since step 8).
   ask: Is it asleep? If not, how many minutes after step 8 is it now?
35. Stop the daemon and the scratch tmux server. The scratch directory stays for evidence; run.sh clean deletes it later.
   run: bash tools/acceptance/run.sh stop
36. Anything else from the walk worth an issue?
   ask: What else surprised you? (none is a fine answer)
