# Torlek Alpha 3 live acceptance

## 1. Start Alpha 3 on a scratch home

1. How this guide works: each step says what to do. A step with a command opens an approval: read the command, approve it, and its output comes back. Type answers in this panel; "none" is a fine answer. Your installed Torlek, its daemon and its sessions are never touched: the build under test runs as profile acceptance, with its sockets, tmux and the scratch project demo under /tmp/torlek-acceptance-UID and its state under this clone's target/acceptance. Claude uses your own login, runs outside greywall and unsandboxed (agents.sandbox = "off"), in the scratch project only. Allow about 75 minutes.
2. Approve the command below. It deletes this walk's earlier scratch home, if any (only directories run.sh made), so item and checkout numbers start at 1.
   run: bash tools/acceptance/run.sh clean
3. Approve the command below. It starts this clone's daemon on the scratch home and prints the scratch and state directories, the profile (acceptance) and the commit under test.
   run: bash tools/acceptance/run.sh start
4. Approve the command below. Every path should be under /tmp/torlek-acceptance- or this clone's target/acceptance; agents.sandbox should be "off" and storage.target_prune_base_ref "refs/heads/main".
   run: bash tools/acceptance/run.sh torlek config show
   ask: Was any path outside those two places, or anything else surprising?
5. Approve the command below. The daemon should answer as profile acceptance, with claude, codex and opencode listed. It may end with exit status 1: the scratch project is untrusted, which this walk does not need.
   run: bash tools/acceptance/run.sh torlek doctor
   ask: Anything in doctor you did not expect?

## 2. The TUI, one Claude session and its temp folder

1. Approve the command below. It opens the TUI in its own opaque window. Click that window to use it.
   run: bash tools/acceptance/run.sh tui-window
   ask: Did the TUI open with project demo in the list?
2. In the TUI press N (shift+n). In the New session form check that Agent says claude (Left/Right changes it), press Tab until First message, paste the text below and press Enter. This session is A for the rest of the walk.
   copy: Say hello in one line, then wait.
   ask: Did card A appear under demo, and did Claude answer? Did Claude ask whether to trust the folder (if so, answer yes in the viewer)?
3. Select A with j/k and press Enter: the viewer shows Claude. Click into the viewer and send the text below.
   copy: Run echo "$TMPDIR" and df -h "$TMPDIR" and show me both outputs, then wait.
   ask: Is TMPDIR a folder of this session under this clone's target/acceptance, on your main disk rather than the /tmp tmpfs?
4. Click the session list. Leave the TUI alone for a minute and watch it.
   ask: Does the TUI stay still while nothing happens (no flicker), and does it still update at once when something changes?

## 3. Todo items: add, image note, edit, hand to a session, queue

1. Click the list and press T: the task view opens. Press a. Type the first text below as Title, press Tab, type the second as Notes, press Tab twice to Project and check it says demo (Left/Right), then press Enter.
   copy: Describe the picture
   copy: Look at image 1 of this item (torlek todo show, torlek todo image get) and describe it in one sentence, then mark this item done.
   ask: Did the item appear in the list? Which number does it have (1 on a fresh home)?
2. Approve the command below. It attaches a screenshot of the TUI to item 1 as an image note.
   run: bash tools/acceptance/run.sh todo-image 1 assets/readme/greenfield-tui.png
3. Approve the command below. It shows item 1 with its image note.
   run: bash tools/acceptance/run.sh torlek todo show 1
   ask: Does it list [Image 1] image/png? Do you see the image note anywhere in the TUI?
4. In the task view select the item, press e, change the Title to the text below and press Enter.
   copy: Describe the attached picture
   ask: Did the new title show at once? Anything odd in the edit form?
5. With the item selected press h. A picker lists the sessions of demo: select A and press Enter.
   ask: Did A receive the item and describe the picture correctly (a terminal UI with a session list)? Did it mark the item done?
6. Press a and add a second item for project demo with the Title and Notes below. Select it, press Q, Q again, and Q once more: it should end queued.
   copy: Write hello.txt
   copy: Create hello.txt containing the line hello from the queue, commit it, then mark this item done.
   ask: Did the queued mark come and go with each Q, and stay on after the third?
7. With the queued item selected press ?.
   ask: What did the explanation say (why it waits or where it went, and what happens next)? Did it make sense?
8. Watch the list for up to two minutes, without pressing anything.
   ask: Did the queue hand the second item to A by itself once A was free? How long did it take? Did the TUI ring the bell (a sound or the window's urgency mark) when A finished something?

## 4. A code-change workflow, from task packet to evidence-bound completion

1. Approve the command below. It files a demo item and starts the code-change workflow on it.
   run: bash tools/acceptance/run.sh code-change "Add greet.sh" "Add an executable greet.sh that prints hello, and commit it on main."
   ask: Did it print three steps: implement, check (requires checks, review) and deliver?
2. In the TUI press Esc to leave the task view, then press F: the workflow view. Select the run and press Enter.
   ask: Does it show step 1 implement, what it waits on and its next action?
3. Wait up to two minutes: the queue places step 1 into a free demo session (A) with its task packet.
   ask: Did A receive the task packet by itself? If nothing came within two minutes, say so and paste the next step's text into A.
4. Only if A did not start in step 3: click A's viewer and send the text below. Otherwise skip this step.
   copy: Run torlek workflow list, begin the ready step of the code-change workflow, and work it to the end following its packet.
5. Claude implements greet.sh, then needs a receipt for the check step: a Waiting on you pane asks you to approve torlek check run checks --project demo. Read it and approve it with y. Decline anything that does not match this walk.
   ask: Did the pane show the exact command, directory and reason? Did the bell ring when it appeared? What did the check return?
6. Claude tries to complete step 2. It should be refused: review is required and nothing in demo can prove it.
   ask: What did Claude report? Did it name review as missing while checks was satisfied by the receipt?
7. In the F view (press F if it closed), open the run with Enter and press a: the owner's completion form. Type the text below in each field (Tab moves), then press Enter.
   copy: owner review in the acceptance walk
   ask: Did the form say which requirements you waive? Did step 2 complete and step 3 deliver become ready?
8. Let Claude finish step 3, deliver. Pull request state is not evidence in this build (#60, Beta 2): a pull request link would be text only, and demo has no remote. If Claude does not continue, send it the text below.
   copy: Complete the deliver step of the workflow; this scratch project has no remote or pull request, say so in the handoff.
   ask: Did the workflow finish, and does F show the last handoff? Anything about the evidence you expected but did not see?

## 5. Resource admission: more work than the budget

1. Approve the command below. From now on each demo agent's work reserves 40% of the CPU budget, 60% with the startup headroom, so only one queued item fits at a time.
   run: bash tools/acceptance/run.sh big-needs on
2. Press N and start a second Claude session in demo with the text below as First message. This is session B. Wait until A and B both wait.
   copy: Say hello in one line, then wait.
   ask: Are A and B both waiting?
3. Press T and add two items for project demo, one with each Title below (Notes empty), and press Q on each.
   copy: Count from 1 to 20, one number per line, running sleep 3 between numbers, then mark this item done.
   copy: Count from 21 to 40, one number per line, running sleep 3 between numbers, then mark this item done.
   ask: Did one item start in A or B within a minute while the other kept waiting, although a session was free?
4. Select the waiting item and press ?.
   ask: Did the explanation say it does not fit the budget, with its charge and what will free it? Was it clear?
5. Approve the command below: the same explanation from the CLI, with the budget in use.
   run: bash tools/acceptance/run.sh torlek queue explain
   ask: Does it tell the same story as the TUI?
6. Wait until the first count is done (about a minute).
   ask: Did the second item start by itself once the first finished?
7. Approve the command below. Demo agents reserve nothing of their own again.
   run: bash tools/acceptance/run.sh big-needs off

## 6. A coordinator and its worker

1. Approve the command below. It starts session C, the coordinator; run.sh remembers it for the next steps.
   run: bash tools/acceptance/run.sh session new --agent claude --prompt "You coordinate workers in this acceptance walk. Reply OK, then wait."
2. Approve the command below. C may start sessions, each with your confirmation, at most 4 an hour and 1 at a time.
   run: bash tools/acceptance/run.sh session grant start-sessions --per-hour 4 --max-active 1
3. Approve the command below. C may message sessions; its workers' questions go to C first.
   run: bash tools/acceptance/run.sh session grant message-sessions
4. Approve the command below. C may see the other sessions' state and questions.
   run: bash tools/acceptance/run.sh session grant observe-sessions
5. Approve the command below. C may end the workers it started.
   run: bash tools/acceptance/run.sh session grant end-sessions
   ask: Does C's card in the TUI name its grants?
6. Select C, press Enter, click into the viewer and send the text below.
   copy: Start one worker in a clone of this project: torlek agent start "$PWD" --agent claude --clone worker-1 --prompt 'Ask your coordinator with torlek agent report --needs-input "Which colour should the button be?", wait for the answer, repeat it in one line, then wait.' Then start a second worker the same way with --clone worker-2 and tell me exactly what torlek answered.
7. A Waiting on you pane asks you to approve C's start of the first worker. Read it and approve with y. The worker is W.
   ask: Did the pane say C asks to start it? Was the second start refused at the cap of 1 active worker, and did the refusal say who can unblock it? Did W start in the clone without asking you to trust its folder?
8. Watch W's card.
   ask: When W asked its question, did its card say C holds the question rather than waiting on you? Did the bell ring?
9. Click C's viewer and send the text below.
   copy: Run torlek agent sessions, answer your worker's question with torlek agent message WORKER blue (WORKER is its session id), then check that it repeated blue.
   ask: Did W receive blue and repeat it? Did the message line on W's card clear once W received it?
10. Send C the text below.
    copy: Your worker is done: end it with torlek agent end WORKER. Then run torlek session grant WORKER observe-sessions and tell me exactly what torlek answered.
    ask: Did W's card leave the list? Was the grant refused as the owner's alone?
11. Approve the command below. It lists demo's checkouts.
    run: bash tools/acceptance/run.sh torlek checkout list demo
    ask: Is worker-1's clone gone, swept when W ended?
12. Approve the command below. It types a message into C as you, from the CLI.
    run: bash tools/acceptance/run.sh session send "Reply with the single word received, then wait."
    ask: Did the message land in C's prompt and get submitted, and did C answer received?

## 7. Storage report and a prune, then project remove

1. End every session: in the TUI select A, B and C in turn and press x, then y.
   ask: Did each card leave the list? Did ending them ring the bell (it should not)?
2. Approve the command below. It makes a clone prune-me of demo, at main's commit.
   run: bash tools/acceptance/run.sh torlek checkout clone demo prune-me
3. Approve the command below. It writes 24 MiB of stand-in build output into prune-me's target/.
   run: bash tools/acceptance/run.sh fill-target prune-me
4. Approve the command below: the storage report, before the prune.
   run: bash tools/acceptance/run.sh torlek storage
   ask: Does prune-me show 25165824 bytes and eligible, with a total? What else does the report show (database, logs, backups, run outputs, session temp folders), and is anything you expected missing?
5. Approve the command below. It prepares a prune plan for checkout 2 (prune-me), deletes nothing and prints the line that confirms it.
   run: bash tools/acceptance/run.sh torlek storage prune 2
   ask: Did it name the target, its size and why it is eligible, and print a confirm line?
6. In a terminal, in the directory these approvals showed, run the confirm line it printed with bash tools/acceptance/run.sh in front, as in the example below with its own numbers, and paste the output here.
   copy: bash tools/acceptance/run.sh torlek storage prune --plan 1 --revision 1 --epoch EPOCH --confirm
   ask: What did it print (operation, removed bytes)?
7. Approve the command below: the storage report, after the prune.
   run: bash tools/acceptance/run.sh torlek storage
   ask: Does prune-me now show 0 bytes, target absent?
8. In the TUI press P: the projects view. Select demo, press d, then y.
   ask: Was demo removed, or refused with a reason? Either is fine: say which, and whether the reason was clear.
9. Approve the command below. It stops the scratch daemon and its tmux server. The scratch home stays as evidence.
   run: bash tools/acceptance/run.sh stop
10. Close the TUI window.
    ask: Over the whole walk, did anything take more than a second or surprise you? Anything else worth noting?
